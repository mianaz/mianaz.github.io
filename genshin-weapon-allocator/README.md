# 提瓦特武器分配工作台 v2.0

本次更新支持自定义武器数量与「幻想真境剧诗」参演名单。网页可离线运行；Python 与 JavaScript 使用相同的场景模型与精确指派求解器。

## 打开程序

直接用浏览器打开 `index.html`。单独的 `genshin_weapon_allocator_v2.html` 是同一程序的独立文件，不需要旁边放其他文件。手机系统的文件预览器可能不执行 JavaScript，请使用能运行本地 HTML 的浏览器。

所有输入修改后点击「重新分配」。程序会清除失效结果并暂停结果导出，避免把旧分配误当成新库存下的答案。

## 修改库存

在「武器库存」中，逐项填写总库存。五星与四星均支持 0、1、2、3、5 等数量。0 表示该武器没有可用成品。

批量设置支持全部西风系列、全部祭礼系列、当前搜索与武器类型筛选结果、全部四星或全部五星。界面会显示即将修改的武器数量；点击「应用库存」后可用「撤销批量」恢复上一次批量修改。后续单项库存编辑或导入配置会清除这项撤销记录。

默认配置仍提供五星每种 1 把、四星每种 2 把，用户可以按实际数量修改。程序输入安全上限为每条库存 1,000,000 把，不是游戏限制。大库存按可使用该武器的本次角色数裁剪计算矩阵，剩余库存仍照常显示。

### 成品与精炼

数量表示精炼完成后的武器成品。既有数据的精炼基线是五星精1、四星精5；改变数量不会改变精炼，也不会把较低精炼自动当成精5。

同一库存条目中的所有副本共用该条目的精炼和候选评分。不同精炼应作为不同 ID 的库存条目，并为各角色分别赋分。例如可以在 JSON 中建立 `fav_sword_r5` 与 `fav_sword_r1`，使用相同名称、不同精炼，分别加入角色候选。网页目前提供数量、锁定和评分编辑；新增不同精炼条目需要编辑 JSON。更改精炼字段本身不会自动计算新性能。

副本编号 #1、#2 等是本程序的分配编号，不是读取自游戏的物品 ID。

## 剧诗操作

切换到「幻想真境剧诗」，在「参演角色」中选取本次完整参演名单。可逐人选择，也可粘贴由逗号、顿号、分号或换行分隔的角色名字。支持角色 ID 和能唯一匹配的部分中文名字。未知或有歧义的名字会阻止整批修改；修正后再提交。

参演来源有三种：

- 自有角色：参与武器优化，占用本人库存。
- 试用角色：记录自带装备，可填写备注，不占本人库存。
- 好友助演：记录好友装备，可填写备注，不占本人库存。

原来在全角色模式停用的角色，也能在剧诗名单中单独选为自有角色。名单外的角色不占本次分配库存。程序会对整份自有角色名单重新求解，不是从全角色结果中截取几行。

### 预留武器

在剧诗模式的「武器库存」表中填写「剧诗预留」。

`可分配数量 = 总库存 − 当前剧诗预留`

例如总库存有 5 把西风剑，需要保留 1 把不参与本轮调配，剧诗可使用 4 把。预留超过库存时程序会报错。全角色模式不扣除剧诗预留。

### 锁定与优先级

剧诗有独立的优先级和武器锁定。优先级未单独填写时继承角色原来的数值；0 仍需要配装，只是不计入总目标分。

默认不使用全角色的武器锁定。勾选「使用全角色方案的武器锁定」后继承全角色锁定；角色单独设置的剧诗锁定优先。剧诗锁定为 `null` 表示明确允许自动分配。

候选评分、玩法标签和前提备注由两个模式共用。在一个模式修改这些内容后，另一个模式也会使用新评分。若移除的候选被其他已保存方案锁定，编辑会被拒绝；先解除相关锁定再删除。

### 保存多份方案

填写方案名并点击「保存 / 覆盖方案」。同名保存覆盖原方案；不同名称可保存多份，最多 50 份。每份保存参演名单、来源、优先级、锁定、预留数量和是否继承全角色锁定。

总库存和候选评分由所有方案共用。载入旧名单时会结合当前库存重新计算；旧方案的预留数量超过新库存时会提示修正。

### 剧诗适用范围

这是开演前为整轮参演角色一次性配装的程序。准备时应列出本轮带入的完整名单。每把本人武器在这轮分配中只交给一位自有角色。

请按当期游戏界面确认元素、特邀、等级、可借用角色和入场人数。程序不验证这些资格，也不选择每幕队伍、分配活力或模拟祝福。此次无法获取足以核实 7.1 挑战中途换装规则的官方正文，程序将计算定位在开演前；游戏中的生效规则以当期提示为准。

## 保存与导出

修改会尝试自动保存到当前浏览器的本地存储。浏览器限制、隐私模式、清理数据、换设备或改变文件路径都可能影响恢复。使用「保存配置」导出 JSON 备份；旧版 JSON 可以直接导入。

配置备份包括总库存、角色候选评分、全角色设置、当前剧诗方案和已保存方案。分配 CSV 包含自有、试用及好友助演行；外部装备不填虚构的偏好分。结果 JSON 还包含库存核对和最优性证书。

## Python 使用

```bash
# 当前配置所选模式
python planner.py --data data.json --out results/current

# 加大西风库存的全角色演示
python planner.py --data examples/favonius_5_each.json --out results/favonius

# 剧诗功能演示
python planner.py --data examples/theater_demo.json --out results/theater

# 使用网页导出的配置，只覆盖本次运行模式
python planner.py --data genshin_allocator_v2_config.json --mode theater --out results/my_theater

# 旧命令入口也识别 v2 的 planning 模式
python allocator.py --data examples/theater_demo.json --out results/theater_legacy
```

`planner.py` 会输出本人配装表 `allocation.csv`、外部角色 `external_characters.csv`、含总量/预留/可用量的 `inventory.csv` 和结果/证书 `result.json`。核心运行不需要安装第三方包。

## 算法变化

设本次需要使用本人库存的角色集合为 C，武器总量为 q，预留量为 r。算法最大化：

`sum(priority[i] * score[i,w] * x[i,w])`

约束为：每位 C 中的角色恰好得到一把武器，每种武器最多使用 `q[w] - r[w]` 个副本，并符合武器类型、候选评分和本方案锁定。试用及好友装备不在变量集合中。

同一武器的多个副本展开为多列。增加数量即增加容量；缩小参演名单则减少竞争者。对每种武器至多保留“有合法候选边的角色数”个副本，额外的相同副本不可能被使用，因此裁剪不改变最优值。每个武器类型使用矩形匈牙利算法求解。结果随后检查库存、物理副本唯一性、原始可行性、对偶可行性与原始/对偶目标相等。

当前求解器只证明给定评分矩阵下的最优值。具体候选分数沿用既有启发式基线；数据版本标签不构成对所有角色、武器和玩法已完成实战验证的证明。

## 演示结果与测试

在其他输入相同时，五种西风武器的每种数量从 2 改为 3、5，121 人全角色最优偏好总分依次是 11,908、11,925、11,937。它们是模型分数，不是伤害百分比。三套结果都没有库存冲突。

`examples/theater_demo.json` 是 6 位自有角色加 2 位自带装备角色的功能演示，含预留和独立锁定，不代表任何一期实际可用名单。它用于验证程序行为。

验证命令：

```bash
# 41 个单元测试方法，其中原求解器含 240 个小型随机问题与穷举比较
python -m unittest -v test_allocator.py test_planner.py

# 可选：需要 Node.js 和 SciPy
python verify_planner.py

# 可选：需要 Playwright 与 Chromium
python browser_test.py

# 修改网页源文件后重建独立 HTML
python build_web.py
```

本次通过 41 个单元测试方法；Python 与 JavaScript 在 104 个完整或随机场景中一致，其中 94 个可行、10 个一致判为不可行；378 个可行子问题的最优目标与 SciPy 独立求解器一致。另通过 28 项浏览器交互检查。

测试环境禁止 URL 导航，浏览器测试把 HTML 直接加载到离线文档。自动恢复测试使用内存 localStorage 模拟验证序列化与恢复；没有把这种测试作为各浏览器 `file://` 持久化保证。禁止本地存储时仍能计算和导出配置。

报告见 `test_report.txt`、`crosscheck_report.json`、`browser_qa_report.json`；界面截图在 `qa/`。

## 文件结构

`allocator.py` / `allocator.js`：库存校验、匈牙利算法与最优性证书。

`planner.py` / `planner.js`：全角色/剧诗场景、外部角色、预留、优先级和锁定。

`app.js`、`template.html`、`build_web.py`：网页交互、布局与独立 HTML 构建。

`data.json`：角色、武器、候选评分和初始配置。资料来源保存在数据中。

`examples/`：可直接导入网页的演示配置。

`results/`：默认全角色、西风每种5把、剧诗演示三份实际求解结果。

所有计算本地执行，不访问游戏账号或修改游戏中的装备。
